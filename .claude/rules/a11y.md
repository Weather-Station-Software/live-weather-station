# Accessibility rules (RGAA / WCAG 2.1 AA)

These are blocking in code review. Any change that violates them gets flagged.

## Links

- Every `<a>` must have a discernible, unique purpose.
- Repeated generic text ("Read more", "Learn more") **must** carry an `aria-label` that names the destination.
- Image-only links must have `aria-label` on the `<a>` (not alt text on the `<img>`).
- Every `href` value must be wrapped in `esc_url()`. Never use `the_permalink()` in an href (double output) — use `esc_url( get_permalink() )`.
- `target="_blank"` always requires `rel="noopener noreferrer"`.

## Buttons

- Every `<button>` must have visible text **or** an `aria-label`. Icon-only buttons need an `aria-label`.

## Interactive elements

- Use `<a>` or `<button>` for interactive elements — never `<div onclick>` or `<span onclick>`.
- Tap targets must meet WCAG 2.5.5 (44×44 px minimum).

## Status conveyed by more than color

- Any status (past/upcoming, active/archived, success/error) shown by color alone also needs a text label or icon+label — never color as the only signal (WCAG 1.4.1).

## Color contrast

- Text on background: minimum 4.5:1 (WCAG AA). Interactive elements: minimum 3:1 for non-text contrast.
- Theme color tokens are the single source of truth — fix contrast in `:root` CSS variables, not per-component.

## Images

- Decorative images: `alt=""`.
- Informative images: `alt` describes the image content, in the site's primary language.
- Never omit the `alt` attribute entirely.

## Structure

- Use semantic elements (`<time datetime="">` for dates, landmarks, headings in order).
- A skip-link ("Skip to content") should exist on any template with a nav before the main content.

## Language

All aria-labels, button labels, and screen-reader text must be in the site's primary language (check the theme's declared locale — do not assume English or French).
